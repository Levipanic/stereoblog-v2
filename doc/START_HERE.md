# Начало работы

Это действующий репозиторий StereoDamage v2, а не шаблон для создания нового
проекта. Установка, конфигурация и команды разработки описаны в корневом
[`README.md`](../README.md).

## Перед первой задачей

1. Прочитайте [`AGENTS.md`](AGENTS.md) — ограничения по данным, безопасности,
   интерфейсу и границам задач обязательны.
2. Найдите активную задачу в [`BACKLOG.md`](BACKLOG.md). Не начинайте следующие
   задачи, пока текущая не проверена владельцем.
3. Для фронтенда или backend прочитайте соответствующий `AGENTS.md` и документы,
   указанные в задаче.

Примеры рабочего цикла, проверок владельца и запросов к агенту есть в
[`AGENT_WORKFLOW.md`](AGENT_WORKFLOW.md).

## Запуск и проверки

Из корня репозитория:

```sh
nvm use
make install-frontend
```

Запустите backend и frontend в двух терминалах:

```sh
make dev-backend
make dev-frontend
```

Основные проверки:

```sh
make test
make check
make e2e
```

`make e2e` использует отдельную временную базу и загрузки. Для локальной проверки
производственной копии используйте только disposable-копию: запуск backend может
автоматически применить миграции. `make audit` читает указанную базу и каталог
загрузок без изменений; точная команда дана в `README.md`.

## Работа над задачей

- Делайте только одну задачу backlog за раз.
- Для совместимости и визуального паритета сверяйтесь с источником v1; см.
  [`V1_REFERENCE.md`](docs/V1_REFERENCE.md).
- Не добавляйте в git production-данные, `.env`, бэкапы или содержимое `uploads/`.
- В конце проверьте критерии задачи, запустите нужные команды и перечислите
  владельцу то, что требует ручной проверки.
